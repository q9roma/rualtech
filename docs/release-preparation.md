Workflow блокирует production, пока репозиторная переменная `PRODUCTION_DEPLOY_ENABLED` не равна `true`. Оставить её выключенной до отдельного разрешения на выпуск. Эта защита подготовлена локально; старый workflow в GitHub автоматически не изменился.

`.env` и `.env.local` используют локальную MySQL `altech`, локальный URL и `MAIL_MAILER=log`. Пароли и APP_KEY не менялись. Секреты не печатались в отчёт и не переносились в шаблоны.

Для будущего сервера подготовлен `deploy/production.env.example`: HTTPS-cookie, debug=false, отдельная учётная запись БД, SSR, выключенный экспериментальный checkout. Пустые APP_KEY/DB_PASSWORD должны быть заданы на сервере. `DEPLOY_SECRETS_ROTATED=false` намеренно блокирует выпуск до реальной ротации. `MAIL_MAILER=log` сохраняется до настройки и проверки рабочей почты.

Перед выпуском подготовить Python-окружение командой `python3 -m venv /srv/altech/catalog-python`, установить `deploy/catalog-requirements.txt` в него и указать путь в CATALOG_PYTHON. ## Перед разрешением выпуска

1. Зафиксировать проверенный локальный код в отдельной ветке и пройти GitHub CI с MySQL.
2. Заменить старые workflow в GitHub. Старый Deploy to Production удаляет рабочие файлы до загрузки архива и перезаписывает `.env`; не запускать его.
3. Подготовить серверные release-каталоги, Node 24, Composer, Python, отдельного deploy-пользователя и службы. Не переводить production-vhost на новый document root до приёмки.
4. Настроить GitHub Environments и новые ограниченные deploy-ключи. Старые HOST/USERNAME/SSH_KEY ещё не изменены; значения secrets невозможно прочитать через API, поэтому соответствие HOST новому IP не подтверждено.
5. На отдельной копии БД проверить миграции, назначение сотрудника, импорт прайса, SSR и очередь; затем восстановление backup и откат. Реальные уведомления и индексацию тестовой копии отключить.
6. Заменить ранее раскрытые учётные данные. APP_KEY менять только после проверки зашифрованных данных и плана перехода; не генерировать его при каждом деплое.
7. После отдельного разрешения пользователя открыть production gate и выпустить проверенный SHA.
