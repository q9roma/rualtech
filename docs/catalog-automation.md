# Автоматические проверки каталога

Актуализация от 12 ноября 2026: готовые кандидаты с подтверждённой идентичностью и фотографии, явно принятые администратором, теперь назначаются через `CatalogPhotoAssignment` и переводятся в `preserved`. Существующие фото не заменяются, черновик автоматически не публикуется. Ниже сохранены описания прежних этапов с отдельным назначением на шаге результата; их утверждения об отсутствии назначения после подтверждения больше не описывают текущую реализацию.

Текущий этап: тестовый контур. Команда `php artisan catalog:automation-check` не имеет опции применения или публикации. Цены, остатки, категории, статусы товаров и галереи сайта не изменяются. Реальный импорт проверяется через существующий `CatalogPriceWorkflow::preview()` в транзакции с обязательным откатом.

## Источники и запуск

Локальная настройка: `storage/app/private/catalog-automation/sources.json`:

```json
{
  "enabled": true,
  "prices": ["C:/path/current-price.xlsx"],
  "media_feeds": ["C:/path/current-media.xml"],
  "image_budget": 20
}
```

Обрабатываются только явно указанные файлы. Исходники не перемещаются и не изменяются. Файл младше минуты откладывается до следующего запуска; максимальный размер 20 МБ. Для XLSX проверяется размер распакованного архива. При смене содержимого по тому же пути новый файл автоматически проходит проверку. Новые имена файлов пока требуют настройки источника: доступа к API, почте или постоянной ссылке VVP ещё нет.

Расписание Laravel: каждые 10 минут, с блокировкой параллельного выполнения. На локальном Windows запускается скрытым процессом через `scripts/start-catalog-automation.ps1`. Он работает при активном процессе и доступной MySQL; автозапуск после перезагрузки Windows пока не настроен. На сервере потребуется обычный постоянный запуск Laravel Scheduler. Отсутствующий или выключенный конфиг делает команду пустой операцией.

## Повторные прогоны и ошибки

Предпросмотр кешируется по содержимому Excel, состоянию товаров, категорий, привязок источников и правилам импорта. Неизменившийся вход не создаёт новые отчёты импорта. Данные сохраняются в частной папке `catalog-automation/prices/<hash>`; `import-preview.json` содержит результат реального импортера с откатом. Завершённые прошлые проверки сохраняются при ошибке нового файла.

`latest.json` содержит состояние последнего прохода по источникам; `last-error.json` — последнюю ошибку самой команды (это историческая запись, она может быть старше успешного прохода). Ошибки отдельных файлов изолированы, другие источники продолжают проверяться. Ошибка источника возвращает ненулевой код завершения. Если прайс/снимок поменялся во время обработки, следующий цикл проверит новое состояние. Тестовый контур ничего из этих отчётов автоматически не применяет.

## Фотографии

XML VVP используется исключительно как дополнительный источник фото. Отсутствие товара в нём не означает отсутствие на складе, удаление или снятие с публикации. Его цены и остатки не применяются.

Сопоставление: уникальная пара бренд + артикул (без изменения внутренней пунктуации), затем точный EAN из сохранённых данных поставщика. Противоречивые EAN у одного товара, отсутствие EAN и неоднозначные совпадения исключают автоматическую загрузку. XML с DTD, сущностями, пустыми или повторяющимися ID отклоняется.

В этой итерации собираются кандидаты для всего каталога, а скачиваются первые обложки уже опубликованной выборки. До 20 новых попыток за цикл, максимум настройки 60. Разрешён HTTPS только `images.vvpgroup.com`, включая каждое перенаправление. Проверяются MIME, декодирование JPEG/PNG/WebP, размер до 15 МБ, стороны от 200 пикселей. Успешные файлы кешируются с SHA-256 и проверяются перед повторным использованием; одинаковое содержимое хранится один раз. Ошибки повторяются не чаще раза в час. Файлы и результаты сохраняются только в частной папке `catalog-automation/images`; существующий публичный локальный пилот Icecat не меняется.

Отчёт `media-<hash XML>.json` содержит сопоставления, исходные ссылки и результаты проверки. `verified` означает технически читаемое изображение и точное совпадение идентификаторов, но не подтверждает комплектацию, отсутствие рекламных надписей или права на использование. Автоматическое назначение обложек пока отключено.

## Следующие этапы

### Полная проверка Icecat в тестовом режиме

`scripts/probe_icecat_catalog.py` проверяет все товары свежего снимка `current-coverage-input.json`, связанного с последним применённым полным прайсом. Неопубликованные товары входят в расчёт, товары только старого прайса — нет. Скрипт повторно использует результаты двух предыдущих пилотов только при совпадении бренда, артикула и EAN; остальные проверяет двумя параллельными запросами. Ошибки отдельных позиций сохраняются отдельно и повторяются при следующем запуске. Ответы 403 не обходятся и учитываются как ограниченный доступ, а не отсутствие товара. При 429 делается пауза перед повторной попыткой.

Результаты сохраняются по каждому ID в `storage/app/private/catalog-automation/icecat-full`. Для строгого совпадения требуется тот же бренд, совпавший EAN и скачанное, успешно декодированное изображение. Совпадение только артикула без подтверждения EAN остаётся отдельным кандидатом; конфликт EAN исключает подтверждение. Демонстрационный доступ Icecat не гарантирует полноту коммерческой базы. Эти проверки не подтверждают визуальную комплектацию и разрешение на дальнейшее использование фото.

После завершения создаётся `coverage.json`: VVP, Icecat, пересечение, объединение, дополнительное покрытие Icecat, непокрытые товары и разбивка по разделам. Проценты считаются по одному списку актуальных товаров; один товар учитывается в объединении один раз. Для VVP учитываются ссылки XML при точном сопоставлении, а не полная загрузка всех изображений — это различие явно указано на странице.

Локальная страница `/catalog/photo-review` автоматически использует завершённый полный отчёт вместо цифр первоначальной выборки. Галерея 67 LG/Philips остаётся прежней и отделена от общей статистики. Новые файлы полного прохода остаются частными и не назначаются товарам. Полный сетевой аудит запускается явно, а не каждые 10 минут.

1. Получить стабильный канал VVP: API, постоянный файл или доставка прайса в выделенный почтовый ящик. Подключить его к этой же обработке, не к кнопкам кабинета.
2. Добавить проверку полноты поставки, резких изменений цен и остатков относительно последней принятой полной версии перед разрешением применения.
3. Подключить рабочий источник Icecat с согласованным доступом: нынешний демонстрационный пилот не является производственным каналом. Затем — проверенные источники производителей.
4. Добавить интерфейс просмотра новых кандидатов фото и правила принятия. До этого ни кандидаты VVP, ни новые товары автоматически не публикуются.

### Техническая проверка фото VVP + Icecat

`scripts/audit_catalog_photos.py` читает подтверждённые соответствия из полного отчёта и не подключается к базе данных. Проверяет все ссылки VVP, хранит исходные файлы и результаты запросов приватно в `catalog-automation/photo-quality/`. Повторный запуск использует кеш успешных загрузок с проверкой SHA-256; ошибки пробует повторно. `--cached` пересчитывает отчёт без сетевых запросов и требует полного кеша.

Критерии технической пригодности: декодируемый JPEG/PNG/WebP до 15 МБ, длинная сторона ≥600 px, короткая ≥200 px. Пустые файлы и точные дубликаты у ≥3 разных моделей исключаются как подозрительные. Это не автоматическое доказательство визуального соответствия, отсутствия текстовой заглушки или правильной комплектации. Небольшая выборка дополнительно просматривается визуально; полная визуальная приёмка не заявляется.

Из подтверждённых Icecat используются загруженные основные изображения. Галерея объединяется с VVP с удалением точных файловых дублей. Для обложки приоритет у основного ракурса источника, затем у разрешения. Никакие существующие назначения фотографий не заменяются. Сохраняются источник, URL, размеры, ошибки и хеши исходных данных отчёта.

Локальный раздел `/catalog/photo-quality` показывает покрытие технически пригодными файлами, поиск и фильтр отсутствующих фото. `/catalog/photo-quality/product/{id}` использует обычный макет страницы товара с отдельной тестовой галереей и реальными ценой, наличием, описанием. Действия заказа в этом просмотре скрыты. Тестовые маршруты и медиа недоступны вне `local`; файлы выдаются только по разрешённому манифесту. Публикация и база товаров не меняются.

Результат полного прохода 09.11.2026: 4087 URL VVP, 206 ошибок загрузки/формата. Технически пригодные изображения: VVP 803/1529 (52,52%), Icecat 210/1529 (13,73%); пересечение 89; вместе 924/1529 (60,43%), без подходящего фото 605. В объединённых галереях 3808 изображений с удалением точных дублей внутри товара. По сравнению с покрытием источниками 1005 товаров автоматический отбор не прошла 81 позиция: 34 имеют только ошибки, 32 затронуты повторами между моделями, 18 — малым размером (причины пересекаются). Повторы могут быть законными семейными изображениями производителя и требуют отдельной оценки, а не признаны заведомо неверными.

Проверки: 4 PHP-теста / 43 утверждения, 3 Python-теста, TypeScript и Vite build; проверка количества и манифеста галерей; просмотр WU300 в браузере с переключением ракурса и описанием. Хеши products, product_categories, catalog_source_products и catalog_import_mappings совпали со снимком до проверки. Публикаций нет.

09.11.2026: по запросу пользователя проверенная галерея подключена к обычному локальному каталогу через ProductMediaQuality, с проверкой id/бренда/артикула/названия. 61 уже опубликованный товар имеет подходящие фото из нового манифеста. Черновики не публиковались. За пределами local слой отключён; база не изменяется. Тестовая галерея и отчёт остаются доступны отдельно.

### Очередь фото после применения прайса (тестовый режим)

После успешного COMMIT `CatalogPriceWorkflow::apply()` вызывает `CatalogPhotoQueue::plan()`. Предпросмотр и откат не создают заданий. Ошибка постановки не отменяет применённые цены: планировщик каждую минуту повторно сверяет последний успешно завершённый полный прайс. Восстановление использует проверенный `staged_hash` и связи поставщика; старые товары вне актуального прайса не обрабатываются.

Очередь хранится в таблице `catalog_photo_tasks`. Ключ — product ID + бренд + полный артикул + название + EAN/набор EAN. Цена, остаток и категория не входят в ключ. Повторный импорт не создаёт дубль. При смене идентичности старое задание становится `superseded`; поздний результат старого обработчика не принимается благодаря lease token. Изображения из действующего проверенного манифеста сохраняются со статусом `preserved`; файлы и назначения не перезаписываются.

Команда `catalog:photos-work` сверяет очередь и обрабатывает до 3 позиций за проход. Состояния: queued → processing → ready/review/not_found/restricted либо retry/failed. Lease 3 минуты, таймаут процесса 120 секунд. Прерванное задание восстанавливается после истечения lease, а после трёх незавершённых/неудачных попыток попадает в failed. Сетевые ошибки повторяются через 5 и 30 минут; третья ошибка требует разбора. not_found проверяется снова через 7 дней, restricted — через 30. `catalog:photos-work --retry-failed` возвращает ошибки в очередь; `--plan-only` только сверяет состав. Блокировка предотвращает одновременные проходы.

Проверка использует локальный XML VVP (сам файл не скачивается автоматически), API Icecat и кеш прошлых проверок (до 7 дней при неизменных идентификаторах). Фото принимаются только с разрешённых HTTPS-хостов, декодируются и проходят ограничения размера/качества. Совпадение MPN без EAN либо конфликт идентификаторов требуют review. Сбой одного источника не мешает сохранить пригодный результат другого. Этот этап ищет основное фото, а не повторяет полный сбор всех ракурсов.

Весь вывод хранится приватно в `storage/app/private/catalog-media-queue/`: результат каждой попытки, исходные идентификаторы, источники, изображения и `latest.json` со статусами. ready означает подготовленного кандидата, а не назначенную фотографию. Скрипт не меняет товары, категории, публикацию, старый манифест витрины или выбранные фото. Конвейер включён только для local/testing. Текущий Windows-планировщик уже работает; после перезапуска компьютера его запускает `scripts/start-catalog-automation.ps1` (автозагрузка Windows не настраивалась).

Проверено: 11 PHP-тестов / 74 утверждения (включая реальные COMMIT и восстановление после сбоя постановки), 3 Python-теста. На текущем прайсе подготовлены 605 заданий, 924 существующие галереи сохранены; повторная сверка создала 0 заданий. Выполнена небольшая реальная партия; фоновые проходы подтверждены журналом scheduler. Хеши products, product_categories, catalog_source_products, catalog_import_mappings не изменились.

### Локальное восстановление пароля

Для пользователя, забывшего пароль, предусмотрена локальная форма `/admin/local-reset-password/{token}`. Токен выдаётся только доверенным оператором через стандартный Laravel Password Broker (публичного endpoint выдачи токенов нет), срок 60 минут, одноразовый. Новый пароль вводит сам пользователь, минимум 12 символов; пароль не передаётся в чат. Форма и POST доступны только в local, защищены CSRF/throttle; страница имеет no-store/no-referrer/noindex. При смене пароля ротируется remember_token. Это не настроенная почтовая служба восстановления для production.


### Единое рабочее место обновления прайса

В админке вход — «Обновить прайс». Каждая загрузка сохраняет собственный адрес и пять разделов: Загрузка → Сравнение → Применение → Фотографии → Результат. Раздел выбирается параметром `section`; переходы только читают данные. Применение запускается отдельным POST после проверки, публикация не меняется.

Сравнение показывает весь отчёт по 50 строк с поиском по названию/артикулу и фильтром решения. Изменённые значения представлены «было → стало». После применения это сохранённый отчёт данного импорта, а не новый расчёт относительно текущей базы.

Фотографии доступны после применения. Очередь встроена в загрузку и ограничена товарами из проверенного staged-файла через идентичность источника. Поле upload_id задания не используется для ограничения: сохранённые фото могут происходить из предыдущих загрузок. Это текущее состояние заданий для товаров выбранного прайса, не исторический снимок. Есть поиск, фильтры, прогресс, диагностика источников и просмотр кандидатов. Кандидаты не назначаются на витрину автоматически. Старый адрес очереди остаётся совместимым, отдельный пункт меню убран.


При применении полного прайса товары, связанные с источником, но отсутствующие во всём файле, сохраняются. Поля availability, stock_free и stock_transit обнуляются, если последнее успешное импортное обновление товара принадлежало этому источнику. Наличие другого источника, обновившего товар позже, не затрагивается. Цена, категория, фото и публикация сохраняются. Предпросмотр не изменяет остатки; пустой файл не допускается к этой операции. При возвращении позиции наличие восстанавливается обычным импортом. Для товара с ценой без наличия витрина использует существующий CTA «Найдите мне это».


## Решения по отдельным товарам в сравнении
В пропущенных строках доступны «Включить в импорт», «Не включать» и отмена сохранённого решения. Включение требует действующей подкатегории. Решение хранится в catalog_import_mappings с rule_code=item-decision, ключом источника и устойчивой идентичностью товара (ID поставщика для supplier-price-32, иначе brand/SKU/вариант поставки). Оно имеет приоритет над общим правилом только для этого товара и действует в следующих прайсах. Ошибки данных и неоднозначная идентичность продолжают блокировать импорт.
Сохранение решения запускает повторную проверку без изменения товаров. Применение — отдельное действие. Новые товары остаются черновиками, существующие сохраняют категории, фото и публикацию. Завершённые загрузки не редактируются. Изменение решения инвалидирует ранее подготовленные предпросмотры через fingerprint. Отмена возвращает действие общего правила.


## Массовое назначение фото и публикация
На шагах «Фотографии» и «Результат» можно назначить проверенные фото всем подходящим товарам одним действием. Перед сохранением показывается фиксированный список, подтверждаемый токеном состояния. Допускаются только ready-задачи текущего применённого прайса с совпадающими name/brand/SKU/EAN, существующими файлами без флагов качества. Спорные результаты и уже назначенные изображения не заменяются. Выбор хранится в catalog_approved_media отдельно от временной очереди; импорт цен его не меняет. У опубликованного товара назначенные фото становятся видны сразу; черновик остаётся скрытым. При изменении идентичности фото перестают выдаваться.
Публикация на шаге «Результат» охватывает все готовые черновики актуального прайса, в том числе из предыдущих загрузок. По текущему batch_id выделяются группы «Новые», «Обновлённые» и «Без изменений». Можно подтвердить все группы или выбранные; сервер фильтрует публикацию и назначение фото по подтверждённым группам. Уже опубликованные учитываются отдельно и повторно не меняются. Нужны действующая подкатегория, название, бренд, артикул и положительная цена. Статус review у фото блокирует массовую публикацию; отсутствие фото само по себе не блокирует её. Товары вне актуального прайса и пропущенные текущим импортом не публикуются. Список пересчитывается под блокировками перед записью; устаревшее подтверждение отклоняется. Повторное открытие не предлагает уже назначенные фото или опубликованные товары. Ни одно действие не запускается автоматически после импорта.


Кнопка подтверждения имеет два режима: «Опубликовать с фото» и «Только добавить фото». Первый выполняет назначение проверенных фото и публикацию готовых черновиков выбранных групп в одной транзакции по одному подтверждённому снимку. В диалоге раздельно показаны количества назначения и публикации, у каждого товара — действия. Второй режим не изменяет статус публикации. Выбор режима в меню ничего не сохраняет. При несовпадении токена ни фото, ни публикация не изменяются.

Проверка спорных фото: на шаге фотографий администратор может подтвердить технически пригодный кандидат либо отклонить фото. Решение проверяет актуальность задания и идентичность товара; само решение не публикует товар и не назначает изображения. Подтверждённое фото доступно для назначения на шаге результата. Отклонённое фото не блокирует публикацию без обложки. Из списка требующих проверки на результате есть переход к спорному фото или редактору данных товара.
