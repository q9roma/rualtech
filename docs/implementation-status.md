# Статус перехода на новую витрину

> Дополнение от 8 ноября 2026: актуальные продуктовые требования находятся в [описании B2B-сайта](product.md), изменения каталога — в [документации импорта](catalog.md). Ниже сохранён датированный отчёт этапов. Упоминания Filament как действующей панели исторические: текущая `/admin` использует React/Inertia, старый импортёр сохранён для совместимости. Числа тестов ниже относятся к указанным этапам.

Обновлено 5 ноября 2026 года. Завершён перенос всех существующих публичных страниц на React/shadcn и подготовлен код второго этапа из [плана развития](commerce-plan.md). Операционная приёмка production остаётся открытой. Готов локальный прототип корзины и оформления на Lunar 1.5; базовый кабинет покупателя реализован, production-процесс заказов остаётся следующим этапом. См. [прототип Lunar](lunar-prototype.md).

## Реализовано

- Целевая модель уточнена: крупный магазин с одним продавцом — Алтех. Marketplace-подход относится к удобству каталога и обслуживания, а не к сторонним продавцам.
- Ручной UX/UI-проход охватил типы экранов витрины и ресурсы Filament на desktop и viewport 390×844. Исправлены мобильная шапка и порядок блоков товара, русские сообщения валидации, чтение кириллицы, описания CMS, приоритеты колонок и подписи админки. Подробная матрица и ограничения — в [плане](commerce-plan.md#ручная-проверка-экранов).
- На изолированной SQLite выполнен сценарий гостевой заказ → регистрация → явная привязка → смена статуса сотрудником → актуальный статус у покупателя. Реальные заявки, платежи и изменения прав в основной базе не выполнялись. Итог: 40 тестов / 667 assertions; TypeScript и client/SSR build проверены.
- Кабинет покупателя: `/register`, `/login`, `/account`, выход; заказы и статусы на shadcn, привязка гостевого заказа только из серверной сессии с явным подтверждением. Регистрация не выдаёт права сотрудника. 39 тестов / 657 assertions, TypeScript и обе сборки успешны. Подтверждение email, восстановление пароля и повтор заказа пока не реализованы.

- Добавлена админка заказов Lunar в существующий Filament: список/поиск/фильтр, состав и контакты, допустимые переходы тестовых статусов, журнал автора/времени/комментария. Права проверяются и на странице, и в операции; устаревшие изменения отклоняются. Страница заказа покупателя показывает актуальный статус. Базовый кабинет реализован: регистрация, вход, собственные заказы и статусы, явная привязка гостевых заказов текущей сессии. Подробности в [документации Lunar](lunar-prototype.md).
- После этого этапа: 33 теста / 556 assertions; TypeScript и client/SSR build успешны. Админка проверена HTTP/Livewire-тестами, интерактивный вход в браузере не выполнялся. Исправлено сохранение email в contact_email Lunar.

- Установлены Inertia Laravel 3.7.0, Inertia React 3.11.0 и React 19.3.1. Точные зависимости зафиксированы lock-файлами.
- Добавлены TypeScript, React-плагин Vite, точки входа клиента и SSR.
- Установлены официальные исходники Button, Input, Badge, Card, Dialog, Label, Textarea, Separator и Select через CLI shadcn/ui. Стандартная тема neutral/new-york; пользовательская зелёная палитра удалена.
- /catalog отображает React-страницу с поиском по названию, артикулу и бренду, категориями, сортировкой, пагинацией и пустой выдачей.
- Фильтры хранятся в URL, сортировка имеет стабильный порядок по id при равных значениях. Параметры запроса валидируются.
- Все 9 типов публичных страниц работают на React/Inertia: главная, каталог, товар, услуги, категория услуг, услуга, блог, статья, CMS. Переходы — Inertia Link. Filament остаётся административной панелью.
- Данные передаются явным списком публичных полей. HTML CMS, статей и услуг очищается Symfony HtmlSanitizer; скрипты и inline-оформление не попадают в React.
- Заявки товаров/услуг работают через существующий JSON endpoint: CSRF, валидация, ошибки 419/422/429, состояние отправки и подтверждение. Общая форма связи сохраняет Bitrix24, Метрика в production учитывает SPA-переходы.
- Добавлены title, description, canonical и noindex для поисковых и категорийных выборок на текущем переходном этапе. Индексируемые категории будут отдельными страницами после нормализации каталога.
- Переключатель STOREFRONT_INERTIA возвращает все публичные страницы на Blade без миграций. По умолчанию новая витрина включена только в local.
- В CI добавлены main, Node.js 24, npm ci, TypeScript, обе сборки, аудиты зависимостей и матрица SQLite/PHP 8.4 + MySQL/PHP 8.4. Ручной workflow выпуска зависит от успешного CI.
- Исправлена изоляция существующего теста главной: миграции SQLite и APP_URL=http://localhost не зависят от локального пути XAMPP.

## Обновление backend и защита

- Laravel 12.24.0 → 12.71.0, Filament 4.0.1 → 4.16.1, Livewire 3.6.4 → 3.8.11, обновлены транзитивные и dev-зависимости. Изменения зафиксированы в composer.lock; assets Filament опубликованы заново.
- Добавлен is_admin с безопасным default=false, явный canAccessPanel и строгие политики для ресурсов. Существующие пользователи автоматически не повышаются в правах.
- Удалены реализация test-login, веб-скрипты создания администратора и webhook с выполнением команд. Остальные корневые PHP-диагностики допускают только CLI.
- Удалены старые deploy/fix/admin workflow и файлы со встроенными секретами. .env.production удалён; .env.local исключён из Git с сохранением локальной копии. История Git не переписана.
- Добавлены secure cookies по умолчанию для production, проверка Host по APP_URL, явные trusted proxies и rate limit заявок.
- Подготовлены SHA-pinned workflow, защищённый ручной выпуск, allowlist артефакта, backup/rollback, Nginx и systemd templates, deploy:check и /ready с SHA релиза. SSR слушает только loopback.
- Dependabot проверяет Composer, npm и Actions еженедельно. Проверка секретов является базовым regression guard, а не полным сканированием истории.

## Что требуется до production

Исходные 77 advisory в 22 PHP-пакетах устранены обновлением зависимостей: текущий Composer audit чистый. Это не гарантирует отсутствия неизвестных уязвимостей. Повторять аудит перед каждым выпуском.

До production нужны фактическая ротация раскрытых секретов, актуальный PHP 8.4 на сервере, GitHub Environment/branch protection, подтверждение SSH host key, настройка служб, успешный CI и staging-прогон. Сценарии деплоя/отката не выполнялись на удалённом Linux-хосте; восстановление backup не проверялось на реальной БД. Linux integration-тесты release helpers добавлены в CI; локально на Windows выполнены синтаксический и статический анализ. Команда deploy:check блокирует выпуск без подтверждения ротации и нужного runtime.

До прототипа Lunar в локальную MySQL была добавлена колонка is_admin. Тестовые товары не добавлялись, существующие пользователи и пароли не изменялись, .env не заменялся. Коммиты, отправка в GitHub, ротация внешних секретов и production-публикация не выполнялись. Локальный PHP остаётся 8.2.12; требование PHP 8.4 проверяется процессом выпуска.

## Следующий шаг

Исправлен локальный запуск: Windows findstr отклонял .env.local с LF-переносами. Проверка заменена на dotenv; start-server.bat и dev-local.bat используют порт 8000. После запуска проверены /ready, /catalog и /admin/login: HTTP 200. MySQL доступна. Для проверки использован реальный dev-local.bat.
